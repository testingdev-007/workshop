30 MINUTES · SCRATCH · NO EXPERIENCE NEEDED

Build your first programme in the time it takes to have a coffee.

Today you'll build a small, working piece of software — a clickable "savings" simulator that grows a number, plays a sound and reacts to you. It's the same trigger → logic → feedback pattern running inside every banking app, trading screen and fintech product you've ever used. By the end, it's yours: built, tested, and complete.

01

Clear the stage

~3 min

Every Scratch project starts with a blank cat. First job: get rid of it and bring in something that fits what we're building.

WHY IT MATTERS

Sprites are UI components. Every screen, button and icon in the apps you use started as a piece someone chose or designed, just like you're about to.

Do this: Right-click the cat sprite in the sprite list and delete it. Click Choose a Sprite — it's below the stage, on the right of the screen — and add the Crystal sprite. Then choose any backdrop you like from the button next to it.
Stuck? Open this

Deleted the wrong thing, or can't find the cat to delete? No harm done — right-click any sprite in the sprite list to delete it, and re-add Crystal from the library if needed.

If the library doesn't show Crystal straight away, use the search box at the top of the library and type "crystal."

02

Give it a memory

~2 min

A programme that can't remember anything can't do much. We'll create one number for it to hold onto: your running total.

WHY IT MATTERS

This is exactly what a database field or an app's "state" is. Your bank balance, right now, is a variable sitting on a server somewhere — conceptually no different from the one you're about to make.

Make a Variable → name it  Savings
Do this: Open the Variables category in the block palette, click Make a Variable, and name it Savings. Tick the checkbox next to it so it shows on the stage.
Stuck? Open this

"Make a Variable" is a button, not a block — it sits at the top of the Variables category, above the orange blocks themselves. Easy to scroll straight past it the first time.

If a pop-up asks "for all sprites or just this sprite" — either works for this project, but "for all sprites" is the simpler default if unsure.

03

Start at zero — and add an explicit reset

~3 min

Whenever the programme runs, it should reset — nobody wants last time's total still sitting there. We'll also give it a dedicated reset you can trigger any time, not just when the programme first starts.

WHY IT MATTERS

The green flag is an event — a trigger. Every time you open a banking app, it runs its own version of this: load the account, reset the screen, start clean.

when green flag clicked
set Savings to  0
Do this: Drag when green flag clicked into the scripts area. Snap set Savings to 0 underneath it. Click the green flag (top right) to test — your Savings should show 0.

The green flag resets it too, but it's a shared button that also (re)starts everything else in the programme. It's worth having a reset that's just a reset — and does nothing else:

when key  r  pressed
set Savings to  0
Do this: From Events, drag a second when key [space] pressed block into the scripts area, and change "space" to "r" using its dropdown. Snap another set Savings to 0 underneath it (drag a fresh one from Variables — don't try to reuse the one from the first script). Press the R key on your keyboard to test.
Stuck? Open this

Most likely the two blocks in either script aren't actually snapped together — there's a small gap. Drag the set Savings to 0 block so its top edge touches the bottom of the hat block above it until you see it click into place.

If the variable checkbox on the stage isn't ticked yet, you won't see the number at all even though it's working — go back to the Variables category and tick the box next to Savings.

If pressing R does nothing, check the dropdown on the key-press block actually says "r" and not still "space".

04

Make it respond

~7 min

This is the main build. When you click the crystal, three things should happen: your total goes up, a sound plays, and the crystal gives a little pulse. Three lines of feedback for one click — that's UX design, and you're about to write it.

WHY IT MATTERS

"When this sprite clicked" is an event handler — the exact mechanism behind every button in every app you've ever tapped. The response you build here is what separates software that feels responsive from software that feels broken.

when this sprite clicked
change Savings by  10
play sound  (whatever's on your sprite)
change size by  10
wait  0.1 seconds
change size by  -10

Why the wait? Without it, the grow and shrink happen back to back so fast that Scratch never actually shows the bigger size — the pulse would be invisible. The 0.1-second pause is what makes the animation something you can actually see.

Do this: Build the stack above on your crystal sprite. For the sound block, check its Sounds tab first — most library sprites already come with one built in — and pick that, or add any short one from the sound library if it's empty. Six blocks, snapped in order. Click the crystal on the stage to test — watch Savings climb, listen for the sound, and see the little pulse. If nothing happens, check every block is actually snapped together with no gaps.
Stuck? Open this

This is the fiddliest step in the whole session — everyone slows down here, so don't worry if it's taking longer than Step 3 did.

If you're running short on time or patience, it's completely fine to build a smaller version first and come back to the sound and pulse later:

when this sprite clicked
change Savings by 10

That's a real, complete, working programme on its own — click the crystal, watch the number go up. Add the sound and pulse back in once that's working, or during Step 5.

05

Make it yours

~4 min

You have a working programme. Now put your own stamp on it — this stops being "the exercise" and starts being something you built.

WHY IT MATTERS

No two working products are identical, even when the underlying logic is the same. Personalisation and product decisions are where a lot of real tech and product careers actually live.

Try any of these: Change the backdrop. Give the crystal a different costume. Change 10 in "change Savings by 10" to a different number. Rename the variable display, or add a second sprite that reacts differently when clicked.

06

Stretch goal — celebrate a milestone

~3 min, if there's time

Optional: make the programme notice when you've hit a target, and say something about it.

WHY IT MATTERS

This is business logic — the same shape as the rules that decide interest, fraud flags, or loan eligibility inside a real financial system: if a condition is true, then do something.

if  Savings > 100  then
say  "You just built your first fintech feature!"  for 2 seconds
Do this: From Control, drag an if / then block into the click script, after the pulse. From Operators, drag a > block into the if's slot, put the Savings variable on the left and 100 on the right. Inside the if, add say ... for 2 seconds from Looks.

Real compound interest
