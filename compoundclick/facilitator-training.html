Vocabulary in one page

The handful of words that cover almost everything you'll need to explain.

Sprite
Any character or object in the project — the crystal, in this build. Each one has its own costumes, sounds, and scripts.
Costume
One of a sprite's possible looks. Sprites can have several; switching between them is how simple animation works.
Backdrop
The background image behind everything on the stage. The stage itself can hold multiple backdrops and its own scripts.
Block
One instruction — "change Savings by 10," "play sound," and so on. Colour-coded by category.
Script / stack
Several blocks snapped together vertically. A sprite can hold more than one separate script.
Hat block
The rounded block that starts a script and can't have anything snapped above it — "when green flag clicked," "when this sprite clicked."
Event
A trigger. Every hat block is an event: a click, a key press, the green flag, a received message.
Variable
A named value the programme remembers and can change — Savings, in this build.

Never used Scratch? 15 minutes, start to finish

If you're prepping cold, work through these in order with Scratch open in another window. Each one is something you'll watch a participant do on the day, so doing it yourself first is the fastest way to be ready for their questions.

1. Open a blank project and find your way around

Go to scratch.mit.edu/projects/editor/ — no account needed, you'll get a blank project with a cat sprite already on the stage. Spend a minute just looking: the block palette (left), the code area (middle, currently empty), and the stage with the sprite pane underneath it (right).

2. Drag a block and watch it snap

Open the Motion category (blue) and drag "move 10 steps" into the code area. Click the block itself — it runs immediately, no green flag needed for a single click-to-test. Drag a "say Hello! for 2 seconds" block from Looks (purple) underneath it — feel it snap into place when the edges line up. Click the stack to run both.

3. Add an event so it runs on its own

From Events (gold), drag "when green flag clicked" above your stack — hat blocks always go on top. Click the green flag above the stage to run it. This is the pattern behind every script in the actual session: an event on top, actions underneath.

4. Make a variable and change it

Open Variables, click "Make a Variable," call it anything, and tick its checkbox so it shows on stage. Drag out "change [variable] by 1" and click it a few times — watch the number on stage move. This is exactly what participants do with Savings.

5. Try deleting something and undoing it

Delete a block by dragging it back onto the palette (or right-click it → Delete Block). Then right-click an empty part of the code area and choose Undo — or press Ctrl+Z (Cmd+Z on a Mac). Getting comfortable with this now means you won't hesitate when a participant panics about "breaking" something.

6. Add a sprite and a sound

Click Choose a Sprite below the stage (right side) and add anything. Click its Sounds tab (top of the middle panel) — most library sprites already have one sound loaded. Drag a "play sound" block from the Sound category (pink) into a script and click to hear it. Check your laptop volume first if nothing happens.

The build, step by step — what "correct" looks like

A terser version of the participant steps, written for glancing at someone's screen and knowing instantly whether they're on track. Full teaching script and timings are in the main facilitator guide.

STEP 1

Clear the stage

Correct: cat sprite gone, Crystal sprite showing in the sprite pane and on stage, any backdrop applied.

WATCH FOR

Someone deletes the cat but never adds Crystal, and is now looking at a totally blank stage assuming something's broken.

STEP 2

Give it a memory

Correct: a variable named Savings exists (Variables category), its checkbox is ticked, and a "Savings: 0" monitor is visible on the stage.

WATCH FOR

The variable exists but its checkbox got unticked at some point — the build still works, they just can't see the number changing, which reads as "broken" to a beginner.

STEP 3

Start at zero — and add an explicit reset

Correct: two separate two-block scripts on the Crystal sprite — when green flag clicked → set Savings to 0, and when key r pressed → set Savings to 0.

WATCH FOR

The key-press block still says "space" (its default) rather than "r" — easy to drag the block and forget to change its dropdown.

STEP 4

Make it respond

Correct: a six-block script on Crystal — when this sprite clicked → change Savings by 10 → play sound → change color effect by 25 → wait 0.1 seconds → change color effect by -25.

WATCH FOR

This is the step people stall on. The single most common issue is a gap between two blocks that looks snapped but isn't — drag the lower block slightly and re-seat it. Second most common: they're clicking the crystal while a different sprite (or the Stage) is selected in the sprite pane, so the script they built never runs.

STEP 5

Make it yours

Correct: anything changed from the default — backdrop, costume, or the "10" in "change Savings by 10." There's no single right answer here.

WATCH FOR

Nothing to watch for — this step is deliberately low-stakes. If someone's anxious about "doing it wrong," that's your cue to say there isn't a wrong answer here.

STEP 6 / EXTENSIONS

Stretch goal and beyond

Correct: an if Savings > 100 then block wrapped around a "say" block, added after the colour-flash blocks in the Step 4 script. Extensions build further from here — see the main guide.

WATCH FOR

The > (greater than) block from Operators has to go inside the if-block's hexagonal slot, with Savings dragged in from Variables on its left — a fiddly three-block nesting that's easy to get the order wrong on.

Troubleshooting reference

Searchable — type a keyword and only matching rows stay visible. Meant for a quick lookup mid-session, not reading top to bottom.

BLOCKS
Two blocks look snapped together but the script doesn't run properly
There's almost always a small gap. Drag the lower block a few pixels and let go near the one above it — it should visibly click into place. If unsure, drag the whole stack slightly; a script that's actually one piece moves as one piece.
BLOCKS
Accidentally deleted or moved a block
Right-click an empty part of the code area and choose Undo, or press Ctrl+Z (Cmd+Z on a Mac) — this reverts the last change to the script. Works for most in-script accidents.
BLOCKS
Blocks have scattered or gone off-screen
Right-click an empty part of the code area and choose Clean up Blocks — it neatly re-stacks every script vertically with space between them.
SPRITE
Accidentally deleted the wrong sprite
There's no confirmed one-click way to bring back a deleted sprite specifically — just re-add Crystal from the library. Takes seconds, no real harm done.
SPRITE
Clicking the crystal on stage does nothing
Check three things in order: (1) the "when this sprite clicked" hat block is actually on top of the stack, not buried under something else; (2) all six blocks are genuinely snapped, no gaps; (3) the Crystal sprite — not the Stage or another sprite — is the one selected (highlighted) in the sprite pane, since the script only lives on whichever sprite was selected when it was built.
VARIABLE
Can't find "Make a Variable"
It's a button at the top of the Variables category in the block palette, above the actual variable blocks — easy to scroll straight past.
VARIABLE
Savings variable exists but the number never shows on stage
The checkbox next to the variable's name in the Variables category needs to be ticked — it's unticked by default when a variable is first created in some flows.
VARIABLE
Two "Savings" variables somehow exist, and only one updates
Usually happens if "Make a Variable" was clicked twice. Right-click the unused one in the palette and delete it, then make sure every block in every script references the same one — check the dropdown on each "change"/"set" block.
SOUND
No sound plays when clicking
Check laptop/system volume first (most common cause by far), then headphones aren't half-unplugged, then that the sprite actually has a sound assigned — open its Sounds tab and confirm one is listed.
RESET
Pressing R doesn't reset Savings to 0
The key-press hat block defaults to "space" when first dragged out — check its dropdown was actually changed to "r," not left on the default.
RESET
Green flag doesn't reset Savings either
Confirm the "when green flag clicked" + "set Savings to 0" script exists and is snapped together — it's easy to build the key-press reset and assume the flag reset is still there from Step 3 when it was never finished.
EXTENSION
The if/then block (Step 6) doesn't seem to do anything
Check the greater-than block is actually seated inside the if-block's hexagonal condition slot (not just floating near it), and that Savings is dragged into its left side with 100 typed into the right. All three pieces have to be properly nested, not just adjacent.
LAPTOP
scratch.mit.edu won't load, or loads very slowly
Likely venue wifi contention with everyone connecting at once, or a network filter blocking the site. Fall back to the offline Scratch Desktop editor if you installed it ahead of time (see the main guide's setup checklist) — it works with no internet at all once installed.
LAPTOP
Everything on screen looks tiny or huge compared to your laptop
That's the browser's zoom level, not Scratch itself — Ctrl+0 (Cmd+0 on a Mac) resets browser zoom to 100%. Separately, the code area has its own small zoom controls in its bottom-left corner if the blocks themselves need resizing.
LAPTOP
The stage suddenly fills the whole screen and the blocks have disappeared
A full-screen stage toggle near the top of the stage was likely clicked by accident. Look for the same control to shrink it back to the normal three-panel view.
PACING
Someone is well ahead of the room
Point them to the extension menu on the participant site, or suggest they help a neighbour — both are good outcomes and neither needs you to intervene. This is common with participants who are confident with logical or structured tools (spreadsheet-heavy roles, for instance) even with zero coding background — naming the "real compound interest" extension directly to them tends to land well, since it maps almost exactly onto a self-updating spreadsheet formula.
PACING
Someone is well behind the room
Don't stall the whole group for one person. Offer the two-block fallback from Step 4 (click → change Savings by 10, nothing else) so they have a complete working thing, and circle back with a helper once the room moves to Step 5.
PACING
Someone hesitates before clicking or dragging anything, or apologises a lot ("sorry, silly question")
This is nerves about the computer, not the content — reassurance beats more explanation. A quick "you genuinely can't break anything here, everything's undoable" tends to unstick people faster than walking through the block again.
